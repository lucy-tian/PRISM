# PRISM Toy Example Using Simulated Data

This directory contains a reproducible toy example demonstrating the complete PRISM workflow using synthetic genotype and phenotype data.

The example uses synthetic African-European genotype data generated by [HAPNEST](https://academic.oup.com/bioinformatics/article/39/9/btad535/7255913).

To reduce runtime and memory requirements, the example is restricted to chromosome 22 and to the African-ancestry subset.

The workflow includes:

1. preparation of the synthetic genotype data;
2. simulation of a phenotype with known genetic architecture;
3. construction of PRISM penalty factors;
4. PRISM model fitting;
5. calculation of polygenic scores; and
6. evaluation of predictive performance.

The annotations used in this example are intentionally simplified. They are designed to demonstrate how variant-level auxiliary information is incorporated into PRISM rather than to reproduce the full annotation scheme used in the main manuscript analyses.

---

## 1. Download and prepare the synthetic genotype data

Download the African synthetic genotype dataset from HAPNEST following the instructions provided with the HAPNEST resource:

[HAPNEST: efficient, large-scale generation and evaluation of synthetic datasets for genotypes and phenotypes](https://academic.oup.com/bioinformatics/article/39/9/btad535/7255913)

The following steps assume that the downloaded genotype data are available as PLINK2 pfiles with prefix:

```text
synthetic_v1_Afr_chr22only
```

with corresponding files such as:

```text
synthetic_v1_Afr_chr22only.pgen
synthetic_v1_Afr_chr22only.pvar.zst
synthetic_v1_Afr_chr22only.psam
```

Which requires you to restrict the genotype data to African-ancestry samples and chromosome 22

Next, generate the allele-frequency reference file used during PGS scoring:

```bash
plink2 \
    --pfile synthetic_v1_Afr_chr22only vzs \
    --freq \
    --out synthetic_freq
```

---

## 2. Simulate the phenotype

The simulated phenotype is generated with SNP heritability:

```text
h² = 0.1
```

### 2.1 Generate the genetic component

Run:

```bash
bash 1a.heritability_determination.sh
```

This script generates the raw genetic component used to construct the simulated phenotype.

### 2.2 Calculate principal components

Run:

```bash
bash 1b.PCA.sh
```

This calculates genetic principal components for the synthetic cohort.

The resulting PCs are included as covariates during PRISM model fitting.

### 2.3 Generate the final phenotype

Run the notebook:

```text
1c.Phenotype_simulation.ipynb
```
This notebook requires a split-assignment file (see [INSERT_SPLIT_ASSIGNMENT] in notebook) specifying whether each sample belongs to the training, validation, or test set.

The file should contain three columns: `FID`, `IID`, and `split`.

Example:

| FID | IID | split |
|---|---|---|
| 0 | sample_001 | train |
| 0 | sample_002 | train |
| 0 | sample_003 | val |
| 0 | sample_004 | val |
| 0 | sample_005 | test |

The `FID` and `IID` columns should match the sample identifiers in the genotype data.

The notebook generates:

```text
final_pheno.pheno
true_causal_effects.txt
true_causal_ids.txt
set_P_q0.tsv
set_P_q20.tsv
set_P_q40.tsv
set_P_q60.tsv
set_P_q80.tsv
set_P_q100.tsv
```

where:

- `final_pheno.pheno` contains the simulated phenotype, sample splits, and genetic PCs;
- `true_causal_effects.txt` contains the simulated effect sizes of the causal variants; and
- `true_causal_ids.txt` contains the IDs of the simulated causal variants.
- `set_P_q*.tsv` files contain the simulated annotation assignments used to generate PRISM penalty factors at different levels of annotation informativeness (q = 0, 0.2, ..., 1.0).

`final_pheno.pheno` is subsequently used as the phenotype input for PRISM.

## 3. Generate simplified annotations and PRISM penalty factors

The toy example uses simplified variant annotations to demonstrate how external variant-level information can be incorporated into PRISM.

Run:

```bash
bash 1e.make_penalty_files.sh
```

This generates PRISM penalty-factor files under:

```text
penalty_files/
```

with filenames:

```text
set_P_q0.rds
set_P_q20.rds
set_P_q40.rds
set_P_q60.rds
set_P_q80.rds
set_P_q100.rds
```
---

## 4. PRISM model fitting

PRISM requires a PLINK-style keep file specifying the samples included during model fitting.

For this example, the fitting script uses:

```text
Afr_train_val.keep.list
```

The keep file should contain two tab-delimited columns, FID and IID, and include individuals in the train and val sets.

The primary model-fitting script is:

```text
2a.snpnet.R
```

The script takes two command-line arguments:

```bash
Rscript 2a.snpnet.R <output_directory> <q>
```

where:

- `<output_directory>` specifies where the fitted model and intermediate results are stored;
- `<q>` specifies the simulated annotation setting.

To fit all six annotation settings, run 

```text
2c.run_snpnet.sh
```
This would produce output stored in `results/q*`


---

## 5. Calculate polygenic scores

After fitting each PRISM model, calculate individual-level polygenic scores using:

```bash
for i in 0 20 40 60 80 100; do
    bash 3.score.sh "results/q${i}"
done
```

The resulting individual-level PGS file is saved as:

```text
results/q0/snpnet.sscore.zst
results/q20/snpnet.sscore.zst
results/q40/snpnet.sscore.zst
results/q60/snpnet.sscore.zst
results/q80/snpnet.sscore.zst
results/q100/snpnet.sscore.zst
```

## 6. Evaluate predictive performance

Predictive performance is evaluated using:

```text
4.eval.R
```

The script takes the model output directory as its only argument:

```bash
Rscript 4.eval.R <model_directory>
```

To evaluate all six annotation settings, run the code below:

```bash
for q in 0 20 40 60 80 100; do
    Rscript 4.eval.R "results/q${q}"
done
```

This produces:

```text
results/q0/snpnet.eval.tsv.gz
results/q20/snpnet.eval.tsv.gz
results/q40/snpnet.eval.tsv.gz
results/q60/snpnet.eval.tsv.gz
results/q80/snpnet.eval.tsv.gz
results/q100/snpnet.eval.tsv.gz
```

These files report the predictive performance of PRISM under different levels of annotation informativeness.

---

## Expected output

After completing the workflow, each model directory should contain the principal outputs needed to examine the fitted PRISM model.

For example:

```text
results/q40/
├── snpnet.BETAs.tsv.gz
├── snpnet.sscore.zst
└── snpnet.eval.tsv.gz
```

where:

- `snpnet.BETAs.tsv.gz` contains the fitted SNP-level effect sizes;
- `snpnet.sscore.zst` contains individual-level polygenic scores; and
- `snpnet.eval.tsv.gz` contains predictive-performance estimates.

The same structure is generated for each value of `q`.

## Notes

- This simulation is intended as a minimal, reproducible example of the PRISM workflow.
- The example is restricted to African-ancestry individuals and chromosome 22 to reduce computational requirements.
- The phenotype is simulated under a known genetic architecture with SNP heritability \(h^2 = 0.1\).
- The simplified annotations are intended to demonstrate annotation-informed penalization and are not equivalent to the complete auxiliary-data framework used in the main PRISM analyses.
- The main analyses use tissue-matched genomic annotations and ancestry-matched fine-mapping results to inform variant-specific penalty factors.
- Runtime depends on available CPU and memory. Restricting the example to chromosome 22 substantially reduces computational requirements relative to the genome-wide analyses reported in the manuscript.
